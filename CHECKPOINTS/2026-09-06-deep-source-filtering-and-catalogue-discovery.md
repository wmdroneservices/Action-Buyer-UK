# 2026-09-06 — Deep Source filtering and catalogue discovery correction\n\n## Problem\n\nDeep Source had two separate failures:\n\n1. A broad model-family match could be treated as an exact generic package match.\n2. Exact same-model pages for packages/accessories not represented by the catalogue could be rejected as mismatches instead of becoming potential catalogue products.\n\nExample:\n\n- catalogue target: DJI Mavic 2 Zoom — Standard Package\n- source page: DJI Mavic 2 Zoom with RC1 Controller\n\nThe source identity must not be priced as the generic Standard Package. If the exact RC1 package does not exist in the catalogue, it must be surfaced for review as a new product candidate.\n\n## Root cause\n\nWorker 1.5.2 improved exact-page discovery, but:\n\n- generic internal package labels were treated as if any same-model page were an exact match;\n- submitCandidate() still discarded variant_match === mismatch;\n- the existing quote_catalog_ai_product_candidates review workflow was not being used by the Research PC.\n\n## Fix — worker 1.5.3\n\n### Identity filtering\n\nGeneric package rows are now treated as broad starting identities, not catch-all evidence destinations.\n\nIf the exact same-model page identifies a distinct:\n\n- controller package;\n- Fly More / Combo / bundle;\n- kit;\n- filter/lens/accessory;\n- battery/charger/case/bag;\n- other named package identity,\n\nthe page is marked as a wrong-target/package mismatch rather than silently matching Standard Package.\n\n### Catalogue discovery\n\nFor a preserved exact same-model mismatch, the worker now creates or reuses a row in quote_catalog_ai_product_candidates.\n\nThis feeds the existing NEW PRODUCT CANDIDATE section in AI Research Centre.\n\nNothing is automatically added or activated.\n\n### Evidence preservation\n\nThe exact same-model mismatch is explicitly preserved for manual review instead of being dropped by the old hard mismatch filter.\n\nThis keeps the exact source URL and evidence visible while also surfacing the missing product/package for catalogue review.\n\n## Expected behaviour\n\n- Exact existing package → normal exact evidence path.\n- Same model, more-specific package → preserved wrong-target finding.\n- Same model, exact identity missing from catalogue → NEW PRODUCT CANDIDATE.\n- Accessories such as an ND Filter Kit → separate accessory candidate rather than aircraft evidence.\n- No automatic catalogue creation, activation or live evidence application.\n\n## Files changed\n\n- tools/gear-ai-local-agent/agent.mjs\n-
